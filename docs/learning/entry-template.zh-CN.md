# 学习记录模板

每完成一个可演示的小步骤，复制这份结构新建或更新对应章节。

## 基本信息

- 阶段：
- 日期：
- Commit：
- 状态：进行中 / 已验证 / 已完成

## 1. 为什么做这一步

用非技术语言描述用户问题，以及如果不做会发生什么。

## 2. 生活化类比

用一个日常场景解释核心概念。类比用于帮助理解，随后必须说明它和真实
实现有哪些不同。

## 3. 完成了什么

列出现在真正可以运行和观察的行为，不只列技术名词。

## 4. 代码模块地图

| 文件或目录 | 作用 | 为什么放在这里 |
| --- | --- | --- |
|  |  |  |

## 5. 背后的技术点

逐一解释概念、数据流、状态变化、可靠性约束和关键取舍。

## 6. 自动化测试

记录：

- 测试文件和测试名称；
- 正常路径；
- 失败路径；
- 实际运行命令和结果。

## 7. 本地手动验证

提供从启动到看到结果的完整步骤，以及成功时应该观察到什么。

## 8. 日志与排错

记录稳定 event 名、关联 ID、error code，以及建议的排查顺序。不得把个人
素材、prompt、模型响应或密钥复制进学习文档。

## 9. 这一步学到了什么

用自己的话说明：

- 原来不理解、现在能解释的概念；
- 实现过程中发现的问题；
- 哪些工程做法可以迁移到其他项目。

## 10. 限制与下一步

明确这一步没有解决什么，避免未来误以为功能已经完整。

## 完成检查

- [ ] 正常路径测试通过
- [ ] 失败路径测试通过
- [ ] 本地手动验证通过
- [ ] 日志中无隐私内容
- [ ] README / Roadmap / Devlog 已同步
- [ ] 学习手册已同步
- [ ] 已创建 focused commit
